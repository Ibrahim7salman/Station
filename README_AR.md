# تحويل نظام محطتك إلى APK لأندرويد

## ما الذي يتضمنه المشروع؟
- تطبيق Android أصلي صغير يفتح واجهة نظام محطتك داخل WebView.
- شاشة إعداد أول تشغيل لإدخال عنوان الخادم المركزي.
- حفظ عنوان الخادم على الهاتف، وزر للرجوع، وأيقونة للتطبيق.
- GitHub Actions لبناء APK تجريبي تلقائياً.

## شرط أساسي
التطبيق ليس قاعدة البيانات ولا الخادم. يجب أولاً تشغيل مشروع الويب المركزي ونشره على عنوان يمكن للهاتف الوصول إليه، ويفضل HTTPS. أدخل هذا العنوان عند فتح التطبيق لأول مرة، مثل:
`https://station.example.com`

لا تستخدم هذا المثال حرفياً. استبدله بعنوان خادمك الحقيقي.

للتجربة على شبكة محلية يمكن إدخال عنوان IP الخاص بجهاز الخادم، مثل:
`http://192.168.1.20:3000`
مع ضرورة أن يكون الهاتف والخادم على شبكة Wi-Fi نفسها، وأن يسمح جدار الحماية بالاتصال. لا تستخدم HTTP غير المشفر على الإنترنت العام.

## بناء APK بواسطة Android Studio
1. نزّل Android Studio وثبّته.
2. افتح مجلد `mahatta_android` من Android Studio.
3. انتظر Gradle Sync وثبّت Android SDK Platform 35 إذا طُلب.
4. من القائمة اختر **Build > Build Bundle(s) / APK(s) > Build APK(s)**.
5. بعد اكتمال البناء ستجد الملف عادةً في:
   `app/build/outputs/apk/debug/app-debug.apk`
6. انقل APK إلى هاتف Android وثبّته. قد تحتاج السماح بالتثبيت من هذا المصدر.

## البناء عبر GitHub دون تثبيت Android Studio
1. أنشئ مستودع GitHub جديداً وارفع محتويات هذا المجلد إليه.
2. افتح تبويب **Actions** وشغّل **Build Android APK**.
3. بعد نجاح المهمة افتح نتيجة التشغيل ونزّل artifact باسم `mahatta-mobile-debug-apk`.
4. فك ضغط artifact لتحصل على `app-debug.apk`.

## تنبيه أمني
هذه نسخة Debug للاختبار وليست إصداراً منشوراً في المتجر. قبل الاستخدام الحقيقي، انشر الخادم عبر HTTPS، واختبر تسجيل الدخول والصلاحيات وسيناريوهات انقطاع الاتصال، ثم أنشئ إصدار Release موقّعاً بمفتاح خاص محفوظ بأمان. لا تضع كلمات مرور قاعدة البيانات داخل APK.
